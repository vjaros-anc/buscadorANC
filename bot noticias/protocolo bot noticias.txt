# 1. Objetivo

Construir un sistema local, ejecutable desde VS Code en Windows, para detectar, consolidar, investigar y priorizar operaciones de concentración económica con posible vínculo con Argentina, con costo monetario de uso igual o cercano a cero.

El sistema debe identificar, entre otras:

- fusiones;
- adquisiciones de empresas;
- adquisiciones de activos;
- compras de participaciones;
- cambios de control;
- joint ventures;
- tomas de control conjunto;
- suscripciones de acciones que alteren el control;
- reorganizaciones societarias con potencial efecto de control;
- farm-ins, cesiones de concesiones o activos productivos cuando puedan constituir una concentración.

El propósito no es determinar automáticamente si una operación debió ser notificada. El sistema debe funcionar como **radar de screening** y producir una lista de casos para revisión humana.

# 2. Principios de diseño

El sistema debe cumplir los siguientes principios:

1. **Costo cero de modelos de IA:** no usar APIs pagas de modelos de lenguaje.
2. **Ejecución local:** Python + SQLite + archivos CSV/Excel.
3. **Trazabilidad:** toda afirmación relevante debe conservar la URL y la fuente original.
4. **No duplicación:** varias noticias sobre la misma operación deben consolidarse en un único caso.
5. **Separación entre hechos y evaluación:** distinguir datos observados de reglas de screening.
6. **Prudencia regulatoria:** “no encontrada en el Registro ANC” nunca debe transformarse automáticamente en “no notificada”.
7. **Reproducibilidad:** las reglas de inclusión, exclusión y prioridad deben quedar parametrizadas.
8. **Revisión humana:** ningún caso debe cerrarse de forma definitiva sin intervención del analista.

# 10. Detección inicial

Primera etapa: aplicar filtros determinísticos.

Una noticia es candidata si:

- contiene al menos una palabra clave de transacción; y
- contiene una o más entidades empresarias potenciales; o
- proviene de una fuente regulatoria/corporativa prioritaria.

Ejemplo conceptual:

```python
def is_candidate(text, keywords):
    t = text.lower()
    return any(k.lower() in t for k in keywords)
```

No descartar automáticamente una noticia solo porque no contenga “Argentina”.

# 11. Nexo con Argentina

La detección de vínculo argentino debe considerar:

1. Mención explícita de Argentina.
2. Subsidiarias argentinas.
3. Activos ubicados en Argentina.
4. Concesiones o licencias en Argentina.
5. Ventas o actividad comercial relevante en Argentina.
6. Comprador o target perteneciente a un grupo con presencia local.
7. Operación global entre empresas que tengan actividad local.
8. Operaciones en sectores especialmente sensibles a activos físicos o concesiones locales.

# 12. Normalización de nombres

El sistema debe convertir variantes a un nombre canónico.

Usar:

- minúsculas/mayúsculas;
- eliminación de signos;
- tabla de alias;
- RapidFuzz para coincidencias aproximadas.

No fusionar empresas solo por similitud de nombre si existe ambigüedad.

# 13. Deduplicación

Objetivo: diez noticias sobre la misma operación deben convertirse en un único caso.

Variables relevantes para la deduplicación:

- buyer;
- target;
- seller;
- fecha;
- sector;
- porcentaje;
- tipo de operación.

Reglas sugeridas:

```text
buyer similar + target similar + fecha ± 30 días
```

= probable misma operación.

Usar una combinación de:

- coincidencia exacta;
- aliases;
- fuzzy matching;
- similitud de títulos;
- ventana temporal.

Toda fusión automática debe registrar un `dedup_score`.

Si el score está debajo del umbral, dejar como “posible duplicado” para revisión.

# 7. Estrategia para minimizar tokens

## 7.1 No enviar HTML completo

Extraer primero localmente:

- título;
- fecha;
- párrafos relevantes;
- nombres;
- fragmentos que contienen keywords.

## 7.2 Limitar contexto

Máximo recomendado por operación:

```text
Fuente 1: 1.500–2.500 caracteres
Fuente 2: 1.000–2.000 caracteres
```

```text

↓

```

## 7.4 Cache

```python
sha256(normalized_text)
```

Guardar respuesta en:

```text
ai_cache
```

# 8. Cuándo usar IA

Crear función:

```python
needs_ai(operation)
```

IA se usa solo si ocurre alguna de estas condiciones:

- comprador o target no se identifican con reglas;
- existen más de dos empresas y la estructura es ambigua;
- hay participaciones antes/después complejas;
- posible adquisición indirecta;
- posible control conjunto;
- joint venture;
- farm-in;
- emisión/suscripción de acciones;
- reorganización societaria;
- no está claro si existe cambio de control;
- Argentina no aparece explícitamente, pero existen señales indirectas;
- fuentes contradictorias;
- múltiples operaciones relacionadas en un mismo artículo;
- resultado de deduplicación ambiguo.

No usar IA si:

```text
“Empresa A adquirió 100% de Empresa B”
```

está explícito y el parser local lo resolvió con alta confianza.

# 13. Fuentes y confiabilidad

Cada fuente debe tener un nivel:


El contexto enviado a IA debe priorizar 5 → 4 → 3.

# 15. Registro ANC

La consulta al registro se realiza localmente igual que en Protocolo 01.

La IA puede ayudar únicamente a generar variantes societarias.

```json
  "Crown Point Energy",
  "Crown Point Energía"
```

Resultados permitidos:


Prohibido concluir automáticamente:
